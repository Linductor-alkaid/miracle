# 视觉定位增强设计（无障碍树 + Set-of-Mark）

> 状态：Proposed
> 版本：0.1
> 更新日期：2026-09-07

> 关联台账：MIR-20260905-001（UI 树通道，已关闭预留）、MIR-20260907-001（决策引用协议，待反馈）

## 1. 背景与问题

P3 真机任务（2026-09-06 取证）暴露：决策→动作链路全通，但 Qwen3.5-4B 对全屏降采样
截图的**坐标回归不可靠**——亮度滑条 swipe 落点偏移导致目标未达成，而
`ModelDoneVerifier` 只确认 done 声明，终态 `Completed` 对用户构成误导。同轮已落地
的诚实呈现（"模型声称完成，未独立验证目标"）是兜底，不是解法。

根因是任务形态错配：让 VLM 做**连续坐标回归**（对 640×1406 降采样图输出 [0,1] 坐标）
天然不稳定；而**离散选择**（从带编号的候选清单里选一个）对 4B 级模型也高度可靠。

## 2. 目标与非目标

目标：

1. 把定位精度从"模型坐标回归"提升到"无障碍树 bounds 精度"（像素级）。
2. 决策引用可校验：模型选择的标记必须存在于本帧标记表，防幻觉引用。
3. 覆盖盲区诚实降级：无障碍树拿不到的场景（WebView 深层、游戏、自绘 canvas）退回
   纯视觉坐标路径，能力位如实声明。
4. 全程不弱化既有边界：同意（树文本出设备前同样受同意约束）、ABI 回调纪律、
   冻结契约演进走上游反馈。

非目标：

- 图像检测器路线（OmniParser/OCR 兜底解析）——留作盲区场景的后续评估项；
- iOS/桌面宿主的同构实现（本设计锚定 Android 宿主，mira 侧接口保持平台无关）；
- 目标结果的独立验证（ILoopVerifier 增强，P3 文档已另登记后续项，与本设计正交）。

## 3. 架构：数据 → 呈现 → 决策引用

核心判断：**无障碍树与 Set-of-Mark 不是并列方案，而是同一方案的两半**——树提供
数据（bounds/语义/可交互性），SoM 提供呈现（把数据变成模型可"看见"的视觉锚点）。

```
无障碍树（Kotlin 快照，与帧对齐）
  ├─ 呈现层（宿主）：
  │    ├─ 视觉：截屏编码前往 Bitmap 叠加编号标记 → PNG 天然带标记，wire 不变
  │    └─ 文本：编号表随 mira.host.tree.v1 上报 → mira structure 摘要进 prompt
  └─ 决策引用层（mira 协议）：
       target_mark: N（编号引用，与坐标并存）→ mira 校验存在性 + 换算 bounds 中心
```

## 4. 宿主 / mira 边界（关键决策 D-1）

**SoM 的实体实现归宿主，mira 只做接口与协议调整。** 三条依据：

1. **时序**：编号必须与帧在同一采集路径完成（树对齐帧 → 分配 mark id → 叠标 →
   编码 → 发布）。mira 的 observe 是拉取语义，无法反向驱动宿主编码时机；mark id
   的权威必须跟着帧走，帧在宿主手里。
2. **先例**：DEC-013 确立宿主负责编码；叠标是编码的一部分。mira 自绘则需在跨平台
   核心引入图像依赖，与轻核心定位相悖。
3. **ABI 回调纪律**：树快照来自无障碍回调，宿主在采集时对齐+编号是有界操作；mira
   介入编号将迫使宿主采集回调等待 native 结果。

miracle 侧新增职责：树快照与帧对齐、mark id 分配（单调递增，进程内唯一即可，跨帧
不复用语义由"校验 ∈ 本帧标记表"保证）、编码前叠标、mark 表随树上报。

mira 侧四处接口/协议调整（登记为 MIR-20260907-001）：

| 调整点 | 内容 |
| --- | --- |
| `mira.host.tree.v1` | 节点可选 `mark`（整数）字段 + 快照级时间戳；编号由宿主分配上报 |
| structure 摘要 | 保留 mark id；长度预算可配置（现 2048 截断对真机可交互节点不足） |
| 决策 schema + compile | `target_mark` 与坐标二选一；校验 mark ∈ 本帧 structure 标记集，换算节点 bounds 中心坐标 |
| 决策摘要/事件 | 呈现 "tap mark 7（显示与亮度）"，R3 确认摘要同样受益 |

防幻觉校验与坐标语义归 mira——它同时持有决策与观察，是唯一能做存在性校验的一层。

## 5. 关键设计决策

**D-2 呈现形态：图上标记 + 文本表双通道。** 文献与实测共识：SoM 增益主要来自视觉
叠加（纯文本"图+表对齐"引用错误率高）。图给视觉锚定，表给精确语义
（"7: 显示与亮度, clickable"），模型交叉验证。绘制规范：只标可交互叶子节点、角标
代替全框（密集页面防互相遮挡）、编号两到三位数、字号以降采样档位可读为准
（640×1406 上需实测标定）；重叠元素只保留最上层可交互节点。

**D-3 引用方式：分阶段演进。** 阶段一（纯宿主）：模型仍输出坐标，SoM/树作为提示
增强——协议零改动，先行量化增益（A/B 对比坐标误差）。阶段二（协议）：`target_mark`
拿到结构性精度（树 bounds + 存在性校验）。坐标路径保留为兼容与盲区降级。中间态
"坐标吸附最近标记"（snap-to-nearest）**不采用**：静默纠偏与静默帮倒笑仅一线之隔，
且破坏决策可解释性（日志坐标与模型意图不一致）。

**D-4 时间对齐：树快照带 monotonic 时间戳，与帧时间戳差超阈值（初值 150ms，
真机标定）时同步重取。** 页面切换瞬间（Agent 动作后高发期）标记表与截图可能来自
两代界面——按旧表点新页。宿主侧对齐 + mira 侧 BoundedSkew 声明双保险；超差时宁可
少标（降级文本表），不可错标。

**D-5 树快照策略（待定，P4 切片一启动前决策）：** 选项 A＝observe 回调内按需全树
dump（实现最简；ColorOS 大页面可能几十毫秒，需实测容量上限内截断）；选项 B＝
无障碍事件驱动维护增量快照（observe 零成本；需处理 TYPE_WINDOW_CONTENT_CHANGED
风暴与服务常驻状态机）。倾向：先 A 后视实测演进到 B——A 的成本发生在 observe
路径（executor worker 上），不在 ABI 回调线程，纪律上可接受。

## 6. 隐私与能力诚实

- 树文本是比截图更结构化的敏感信息（全屏控件文本、输入框 hint）：出设备（进决策
  prompt）前同样受会话同意约束；PasswordField 内容本不可得，联想/缓冲文本过滤后
  不上报。
- 节点过滤：`visibleToUser` + 可交互（clickable/scrollable）或有文本/描述，叶子
  优先；单帧节点数上限（初值 64，真机标定），超限按可交互优先截断并在标记表头
  如实标注（"截断"）。
- 盲区降级：宿主上不了树（WebView 深层/游戏/canvas）就不上报 mark——mira 的
  target_mark 校验自然要求模型走坐标路径；`accessibility_completeness` 能力位
  如实反映树质量。
- 日志与事件：mark 表引用只留摘要（编号 + 描述截断），与截图引用同等纪律。

## 7. 风险

| 风险 | 缓解 |
| --- | --- |
| 叠标遮挡内容影响决策 | 角标 + 只标可交互叶子；A/B 实测（切片二验收即对比实验） |
| 陈旧标记表（跨代界面） | D-4 时间对齐 + 重取；超差降级 |
| 小模型编号幻觉 | mira 存在性校验 fail-closed；不存在 → violation → 既有 rejection 反馈重试 |
| 无障碍服务被系统限制（厂商电池策略） | 既有 P2 经验（oneplus-ace3.md）；能力位降级如实上报 |
| 上游协议排期不确定 | 阶段一（坐标增强）不依赖上游，先行交付增益 |
